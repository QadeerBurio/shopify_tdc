# TDC review 149610

## Backend implementation and contract

The TDC account and brand service is in the separate local checkout at `E:\Development\Test\server`. See its `docs/shopify-review-149610.md` for setup, database indexes and the integration test. The app delegates account authentication and brand selection to that service and reads the persisted association when Home loads. The Shopify app no longer uses a brand ID from an install URL, OAuth state, or a Shopify staff email to authorize a link. Disable any legacy backend link operation that still authorizes by those inputs alone.

### Start a brand connection

- The app sends `POST /api/shopify-app/link-shop/start` to `BACKEND_API_URL` with `X-API-KEY: <SHOPIFY_APP_API_KEY>` and JSON `{"shop":"<canonical-shop>.myshopify.com"}`. The app takes the shop from the authenticated Shopify Admin session. The app and backend must use HTTPS.
- Return HTTP 200 and JSON `{"authorizationUrl":"https://<tdc-connect-origin>/<browser-flow-with-opaque-ticket>"}`. The app allows only the exact HTTPS origin configured by `TDC_CONNECT_ORIGIN`, which defaults to the backend origin. The backend must generate the URL and use its existing TDC sign-in experience.
- Create an unpredictable, short-lived, single-use ticket bound server-side to the Shopify shop. Bind it to the TDC browser session used for sign-in and require explicit confirmation of the shop and selected brand in a CSRF-protected write. Offer only brands the current user may manage and recheck that permission at confirmation. Reject expired, redeemed, or mismatched tickets. Browser input may identify a brand to select. Only verified TDC membership and the server-side ticket determine authorization and shop identity.
- Persist through the existing brand/store association. Enforce uniqueness for the canonical shop and prevent overwriting either side of an existing association with a different shop or brand. Perform the association check and write atomically, and treat confirmation of the exact same association as successful. Return HTTP 409 if a conflicting association appears before setup completes. Start failures should use HTTP 401/403 for authorization failures, 409 for conflicts, and 5xx for temporary failures. The browser flow should show recovery instructions for failed sign-in, missing permissions, expired tickets, and transient errors. On success, guide the merchant back to **Shopify Admin > Apps > tdc**.
- The app reloads `GET /api/shopify-app/brand?shop=<canonical-shop>` through the same authenticated server integration. Return 404 for unlinked shops and a complete persisted brand object with `id`, `brandName`, `roi` and `discounts` for linked shops. Use a server error for temporary failures. A browser URL alone does not establish that setup succeeded.

### Make discount saves idempotent

- The existing `POST /api/shopify-app/discount` now receives `Idempotency-Key`, a SHA-256 hex digest of the JSON array `[shop, shopifyDiscountId]`, and a `brandId` field in addition to the existing `shop`, `code`, `discountType`, `discountValue`, `shopifyDiscountId`, `startsAt`, and optional `endsAt`.
- Authenticate `X-API-KEY`, verify the shop is still associated with the supplied brand at write time, and upsert by the canonical shop and Shopify discount ID. Repeated or concurrent requests for the same completed operation must return 2xx without duplicating a rule or downstream side effects. Return a conflict if the same key identifies a different operation or the brand link changed. A retry after a committed write whose response was lost must return 2xx.
- Confirm that the deployed backend supports this contract before relying on retries. The Shopify app's MongoDB journal prevents a repeat Shopify creation after the ID is recorded. If the create response was lost, the original Shopify code and request tag recover the ID. A retry button never calls Shopify create. Older failures without a journal entry are outside automatic recovery and may need reconciliation with the existing backend.
- Generate the Prisma client with `npm run setup`. The journal uses the same MongoDB database as Shopify sessions, with `MONGODB_DB_NAME` defaulting to `prisma`. Local regression command is `node tests/run-review-regressions.mjs`.
